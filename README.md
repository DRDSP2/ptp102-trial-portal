# PTP-102 Veterinary Laminitis Trials

Clinical trial management portal for **INAD-PTP102-2025**, an investigational
equine laminitis drug. React 18 + TypeScript SPA originally generated by
UIBakery and currently being migrated to a Supabase + Vercel backend.

> **Status: mid-migration.** Auth, registration, and secure file upload/download
> use Supabase. Almost everything else still reads/writes browser
> `localStorage` via the `uibakeryDataMock.ts` shim. See
> [Data layer](#data-layer) below.

---

## Quick start

```bash
# 1. Install dependencies (Node 20+)
npm install

# 2. Copy and fill in env vars
cp .env.local.example .env.local
# Required:
#   VITE_SUPABASE_URL
#   VITE_SUPABASE_ANON_KEY
#   SUPABASE_SERVICE_ROLE_KEY   (server-side only; never expose to browser)

# 3. Start the local API server (mirrors Vercel /api/* on :3001)
npm run dev:server

# 4. In a second shell, start Vite (proxies /api -> :3001)
npm run dev

# Tests, lint, build
npm run test            # Vitest (jsdom) — 92 specs across 18 files
npm run lint            # ESLint flat config
npm run build           # Vite -> dist/
```

The app uses **HashRouter**, so it works on static hosts (including IPFS).
Default dev URL: `http://localhost:5173/#/`.

## Data layer

The most important thing to understand about this codebase: **two data
backends coexist**.

### A. Supabase (real backend)

Used only for:
- Auth: `AuthContext` calls `supabase.auth.signInWithPassword`, `getSession`, etc.
- Vet registration: `POST /api/register` writes the auth user.
- Secure file uploads: `POST /api/upload` (Bearer-token authed) → `private-uploads` bucket with RLS.
- Signed downloads: `GET /api/download?path=…` issues 5-minute signed URLs after `canAccessPath` ACL.

### B. UIBakery localStorage mock

Everything else — patients, treatments, assessments, lab results, audit logs,
shipments, etc. — flows through `src/lib/uibakeryDataMock.ts`. The Vite alias
in `vite.config.ts` redirects `@uibakery/data` to that file, so every
component hook (`useLoadAction`, `useMutateAction`) reads/writes
`localStorage` keyed under `ptp102_mock_*`.

**Implication:** clearing browser storage wipes all clinical data outside of
auth and file uploads. The migrations under `src/migrations/` describe a
schema that is **not actually applied to the live Supabase project** — see
the next section.

### Database migrations — important caveat

`src/migrations/applied.txt` lists 22 migrations as applied (timestamps 2025-11-04
to 2025-11-07), but those entries reference an earlier UIBakery-managed
database. Probing the live Supabase project shows that **only the `patients`
table and the `private-uploads` storage bucket exist**. All other expected
tables (`veterinarians`, `clinical_notes`, `treatments`,
`clinical_assessments`, `audit_logs`, `ncie_shipment_log`, etc.) are missing.

The 5 newest migration files are also not in `applied.txt`:

```
1738600000_add_conflict_of_interest_to_vets.sql
1738700000_add_enrolled_by_vet_to_patients.sql
1738800000_enhance_ncie_shipment_vet_link.sql
1781380365_clamp_obel_grade.sql
1781380366_private_uploads_bucket.sql   (this one IS applied — bucket + RLS exist)
```

**To stand up a real backend, all 27 migrations need to be applied in order to
the Supabase project**, then `applied.txt` should be regenerated to reflect
reality. Do not trust `applied.txt` as currently committed.

## E2E secure-upload script

`scripts/e2eSecureUpload.ts` exercises the upload/download pipeline end to end
against the **real Supabase project**. It:

1. Creates two temp users via the service-role key.
2. Uploads as user A, verifies A can download.
3. Verifies user B is forbidden (both via `/api/download` and direct storage RLS).
4. Verifies the public URL is inaccessible.
5. Cleans up users + uploaded object.

**Warnings:**
- Run only against a non-production Supabase project.
- Requires the local API server (`npm run dev:server`) to be running.
- The script's `main()` executes on import — never `import` it from another
  module. Run it directly: `npx tsx scripts/e2eSecureUpload.ts`.
- If interrupted before the cleanup `finally` block runs, it can leave
  `e2e-a-*@example.com` / `e2e-b-*@example.com` users behind. Delete them
  via the Supabase dashboard or service-role API.

## Conventions

- Path alias: `@/* → src/*`. Use it for all in-repo imports.
- The alias `@uibakery/data` is special — it resolves to the localStorage mock
  via Vite. Don't import the published `@uibakery/data` package directly.
- Run `npm run lint` before committing. Today the codebase has 0 errors and
  ~225 warnings (mostly `any` and unused vars in the legacy mock file).
- Tests live in `src/__tests__/`. Add new specs there and prefer
  Testing Library + Vitest matchers.
